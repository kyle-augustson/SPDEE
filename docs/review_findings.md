# Code review findings from the module sweep

Findings recorded during the comment/dead-code sweep of the pre-existing
modules.  Nothing here was changed in code; each item is a decision for the
maintainer.  Confidence: H = confirmed numerically or by direct inspection,
M = algebra or reading solid but impact untested, L = minor or maintenance.

| # | Where | Finding | Conf. |

| 20 | `spdee/ir/expressions.py` `_make_product` | `p * 2`, `S * N2`, `Div(v) * rho0` are rejected (left operand always taken as the scalar) while the reversed order works.  FIXED: for scalar × scalar the background factor is the coefficient whichever side it is on. | H |
| 21 | same file, division | `Grad(p) / rho0` fails with "Expected a background scalar value".  FIXED: division by any background scalar expression multiplies by its reciprocal (a bare value when SymPy-backed, else a cached background field with a `ReciprocalComponent`); `1/rho0 * x` works through `__rtruediv__`. | H |
| 22 | `spdee/ir/tasks.py` `bind_parameters` | Symbols carrying assumptions (`Symbol('Ek', positive=True)`) are not matched by string keys; binding silently no-ops. The fd2 collocated (`compiler.py`) and staggered (`staggered_general.py`) cores call `bind_parameters` only when `params` is non-empty, so an unbound symbol with `params=None` still surfaces as their later "Cannot convert expression to float"; sh_fd and Dedalus check their own. | M |

| 26 | `spdee/applications/solar_eigenmodes.py` | Ω₀ hard-coded in the polytrope builder but a parameter in the ball builder; dipole with `geometry='ball'` and default `r_inner=0.71` is singular at the origin and not validated.  FIXED: `omega0_nHz` is a parameter of both builders with the module default `OMEGA0_NHZ = 456.0` (the same float as before, pencils unchanged); `make_solar_shell_system` and `make_polytrope_system` (Le > 0) raise on a ball unless the dipole's r_inner is 0; with r_inner = 0 the dipole is the uniform field ẑ at the origin and `make_dipolar_B0` / `make_dipolar_B0_curl` give the origin node that limit (cos θ, −sin θ, (4α/3L) sin θ) instead of the 0/0 of the closed form (`tests/test_solar_eigenmodes.py::TestBallDipole`). | 27 | `spdee/backgrounds/solar.py` `_auto_blend_radius` | Returns 0.55 silently when no crossing exists; latitudinal means unweighted by sinθ; raw and prefit evaluators differ below the data.  FIXED: no crossing raises ValueError naming the scanned extent and the rates, and the detection runs only when the blend is on (`blend_radius_used` / `blend_radius_resolved` are None otherwise); every latitudinal mean is sin θ-weighted (Gauss-Legendre weights on the pre-fitted samples), which moves the raw core rate 432.68 → 432.34 nHz and the detected tachocline 0.686 → 0.709 (raw) and 0.685 → 0.707 (prefit) — the crossing is shallow — inside the tests' 0.65-0.72 and raw/prefit 0.01 anchors, whose docstrings now quote 0.71. Note that with the blend on the tanh transition (width 1/200) now reaches the base of the Bekki shell: Ω(0.71, equator) is 442.7 nHz instead of 450.6 (the raw value), 453.65 vs 453.95 at 0.72, unchanged from 0.73 out, so the Model S shell runs with `uniform_core_blend=True` (tests/test_solar_shell.py, test_solar_eigenmodes.py) see a 1.8 % slower inner boundary; both suites still pass; both evaluators return the core rate below the inner data radius (only the pre-fitted samples have one, at 0.5), and the docstrings say so. Ball profiles are also even in r now, so a finite-difference probe across the origin evaluates |r| instead of raising, which lets the collocated core compile the ball system. | L |

## Maintenance

- Duplicated stencil/anchor logic in the collocated compiler and CompiledProblem; layout relies on row index = column offset.
- Staggered: 2-point stencil loops appear four times; the Coriolis adjoint-pair block is copied between the inertial and compressible assemblers; `StaggeredCompiledMatrices.mhd` is set but never read; `_inv_sin_with_pole_closure` has two unused parameters kept for a test caller.
- Scripts: `inviscid_order_sweep(_mpi)` and `polytrope_spectrum` / `polytrope_spectrum_mpi` are near-duplicate pairs.
- Tests: `test_grad_div_new.py` and `test_curl_cross_new.py` carry a `_new` suffix with no older counterpart.

## Fixed during the sweep and the full-sphere audit

- `tests/test_backends.py`: the two "stub raises NotImplementedError" tests now assert that `sh_fd` and `dedalus` require a grid.
- `tests/test_equations.py`: the name-collision test now uses a scalar and a vector of the same name instead of skipping unconditionally.
- `spdee/applications/solar_eigenmodes.py`: the `tests/` path inserted for the `test_solar_shell` import pointed at a nonexistent directory; it now resolves from the repo root.
- `scripts/polytrope_spectrum_mpi.py`: module docstring stated the eigenvalue convention backwards.
- `spdee/backends/fd2/staggered_compile.py`: items 7 and 29 above (sign alignment of the pressure/continuity blocks; south-pole guard), found by the entrywise seed comparison commissioned for the paper.
- `spdee/backends/fd2/compiled_problem.py`: importing pypardiso loads `libmkl_rt`, whose FFTW-interface symbols shadow the FFTW that Dedalus links, so after any m=0 BVP solve every Dedalus transform in the process fails with "FFTW could not create plans" (this made all Dedalus tests fail in the full suite). PARDISO is now opt-in with `SPDEE_USE_PARDISO=1`; the default BVP solve is SuperLU.
